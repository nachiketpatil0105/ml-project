Check and reproduce everything

The website shows the main reasoning, figures and tables. The repository has the code, the exact splits and all results so that you can check them.

Repository:

Data access

We use the mini part of the Music Streaming Sessions Dataset (Brost et al., WWW 2019), released for the WSDM Cup 2019. The official download is no longer offered, so we took the two files from the public archive github.com/suhani6/spotify-skip-analysis. They are in the data/ folder: log_mini.csv (session log) and tf_mini.csv (track features). No script changes them.

Steps to run

Run these from the project folder with Python 3.12 or newer (we used 3.13). The exact package versions are in requirements.txt and in the table below.

python3 -m pip install -r requirements.txt
python3 python/01_data_understanding/analyze.py
python3 python/02_preprocessing/make_split.py
python3 python/02_preprocessing/describe_features.py
python3 -m unittest discover -s python/02_preprocessing -v
python3 python/03_tuning/run_experiments.py --trials 40 --top 5
python3 python/03_tuning/make_plots.py
python3 python/04_final_test/run_final.py
python3 python/04_final_test/make_plots.py
python3 python/05_error_analysis/analyze_errors.py
python3 python/05_error_analysis/make_plots.py
python3 python/06_explorer/export_explorer.py
python3 python/07_extra_experiments/run_extra.py
python3 -m http.server

Then open the address that http.server prints. The tuning step (run_experiments.py) is the slow one (about 1 hour 45 minutes on 2 CPU cores for the submitted run; less with more cores). It saves its progress, so you can stop and continue. The scripts do the work; each is short and prints what it does. A walkthrough notebook, notebooks/walkthrough.ipynb, loads the saved results and goes through the steps in order without re-training anything. The extra-experiments step takes about 10 to 20 minutes. Setting QUICK=1 runs any step on a small subset into a results_quick folder, as a smoke test.

Extra experiments

All extra experiments are scripted and saved. The Optuna search, the settings grids, the feature-group ablation and the threshold curve are in python/03_tuning/results/ (development.json, optuna.db). The "change one thing" experiments (removing a feature group or the start/end reason shares, adding skip_1/skip_3 history, audio deltas or a per-song skip rate, swapping the model, and floor(L/2) instead of ceil(L/2)) are made by python/07_extra_experiments/run_extra.py and saved in python/07_extra_experiments/results/extra_experiments.json. Early hand-run versions of some of these, made with an older pipeline, are replaced by these scripted runs.

Data, privacy and credentials

  • No personal information. The data has no names, no user IDs and no song titles or artists. Session and track IDs are anonymous codes (for example 0_00006f66-…) that come with the dataset; there is no way to link a session to a person or to link two sessions of the same person.
  • No credentials. The project uses no API, no API keys, passwords or tokens, and nothing is downloaded at run time. Nothing secret is stored in the repository.
  • Why the data files are in the repository. The official download is no longer offered, so the two CSV files are included only so that the results can be reproduced. They are the mini partition of the Music Streaming Sessions Dataset (Spotify, WSDM Cup 2019) and stay under the terms of that release. They can also be taken from the public archive named above. No script changes them.
  • What leaves the computer. Nothing. The website is static; the explorer runs the model in the visitor's browser and sends no data anywhere.

Exact preprocessing and splits

  • Feature code: python/shared/features.py. The list of allowed input columns: python/02_preprocessing/results/feature_summary.json.
  • Split: 80/20 by session with seed 42, saved in python/02_preprocessing/results/session_split.json. Fold assignments of the cross-validation (4 seeds): python/03_tuning/results/cv_folds.json.
  • All Optuna trials are in python/03_tuning/results/optuna.db and summarised in development.json.

Hosting

The site is plain HTML, CSS and JavaScript and is hosted on GitHub Pages (link on the home page). The pages read the result files directly from the python/*/results folders, so the numbers you see are the numbers in the repository. To view the site on your own computer, run python3 -m http.server in the project folder and open the address it prints; opening the HTML files directly from disk does not work.
