The project proposal

The seven fields below are the proposal as we submitted it, word for word. Below them is a table of what changed while we carried the project out, and why.

Research question

Can classical machine learning models predict whether a user will skip upcoming tracks in a streaming session, using only the user's interaction history from the first half of the session and the acoustic features of the upcoming tracks? Specifically, to what extent do behavioural momentum (recent skip patterns) and acoustic similarity to previously unskipped tracks explain skip decisions, compared with a static track-level signal such as popularity?

Problem and intended claim

In music streaming, a skip is the main form of implicit negative feedback. Recommending tracks that are skipped breaks the listening experience and can reduce user engagement. We will predict the binary skip outcome for every track in the second half of a listening session, using only the user's observed behaviour in the first half and the acoustic properties of the upcoming tracks.

Our intended claim is that feature-engineered classical models, which capture session behavioural momentum (skip rate, recent skip streaks, playback start reason of the last observed track) and the acoustic distance between a candidate track and the user's unskipped history, will clearly outperform simple heuristic baselines. This should hold without deep sequential architectures and without target leakage from the offline logs.

A useful answer is a measurable gain over the baselines on unseen sessions in Mean Average Accuracy (MAA), together with evidence of which feature groups (popularity, behavioural momentum, acoustic similarity) contribute most to that gain.

Data plan

We will use the mini partition of the Spotify Sequential Skip Prediction Dataset (Music Streaming Sessions Dataset, Brost et al., WWW 2019), originally released for the WSDM Cup 2019 challenge. As the original release is no longer available, we access the mini files through a public repository archive (suhani6/spotify-skip-analysis).

The data consists of two relational tables:

  • Session log (log_mini.csv): approximately 168,000 observations across 10,000 listening sessions of 10 to 20 tracks. Each row is one track play within a session, identified by session id and session position.
  • Track features (tf_mini.csv): approximately 50,000 observations. Each row is one unique track, identified by track id, and is joined to the log on this key.

Variables to be used:

  • Session context: session position, session length, premium status and context type (for example user collection, catalog, editorial playlist, radio).
  • Observed first-half history: skip labels, playback start reason, pause and seek indicators.
  • Candidate track descriptors: duration, popularity estimate, danceability, energy, loudness, tempo, valence, acousticness, speechiness and the 8-dimensional acoustic vector (acoustic_vector_0 to 7).
  • Target: binary skip indicator skip_2 for tracks in the second half of each session.

Each session is partitioned at K = floor(L/2): the first K tracks form the observed history and tracks after K form the prediction window.

Baseline and candidate methods

The modelling will proceed in stages:

Simple baselines (no learning): (1) global majority class; (2) session-history majority (user's first-half skip frequency); (3) copy-last-skip, which assumes the final observed skip state continues and tests session inertia; (4) popularity only, using the popularity estimate as the sole signal to benchmark static popularity.

Stage 1, Regularized Logistic Regression: an interpretable linear baseline trained on session context and behavioural momentum (first-half skip rate, recent skip streaks, start reason of the last observed track). Its coefficients quantify the predictive power of historical context alone.

Stage 2, Random Forest: incorporates candidate track acoustic features and acoustic similarity metrics (cosine and Euclidean distance between candidate acoustic vectors and the centroid of unskipped first-half tracks) to capture non-linear effects.

Stage 3, Boosted Decision Trees: our primary model family. BDTs excel on tabular data and capture complex feature interactions, such as high recent skip frequency combined with large acoustic divergence from the user's preferred centroid.

We will conduct feature-group comparisons (popularity only vs. plus history vs. plus acoustic similarity) to quantify the marginal gain from each representation.

Evaluation plan

Validation: sessions will be split by session id into 80% train and 20% test, so that all tracks of a session stay in one partition. Within the training partition, hyperparameter tuning and model selection use 5-fold cross-validation grouped by session id. The 20% test set is used once, at the end. Within each session, the first half is the observed history and the second half is the prediction target.

Metrics: the primary metric is Mean Average Accuracy (MAA). It evaluates accuracy position by position across the prediction window and weights the immediately upcoming tracks more, which reflects how a streaming queue is used. Secondary metrics are first-prediction accuracy (the next track) and ROC-AUC for ranking quality. Bootstrap confidence intervals over sessions will be reported to check whether differences between models are meaningful.

Leakage prevention: the strict boundary K = floor(L/2) is enforced. For all tracks with t > K, every interaction attribute (skip flags, playback end reason, seek counts, pause flags, start reason) is removed before feature extraction. History features and the unskipped-track centroid use only the first half of the same session. Scalers and any learned statistics are fitted on training sessions only.

Likely challenge

The main challenge is target and temporal leakage in the offline playback logs. Attributes recorded when a track stops playing, mainly the playback end reason and seek counts, directly disclose whether the track was skipped and would artificially inflate performance if used.

We will address this with an isolated preprocessing pipeline that enforces the observation boundary: for each session, all tracks past the midpoint are stripped of their concurrent interaction variables before any feature engineering. Features for future tracks will be restricted to their acoustic descriptors and summary statistics computed only from the first half of the session. A written list of permitted input columns will be used to audit every model.

Track-specific plan (ES 335: interaction)

We will develop an interactive Streamlit dashboard that simulates a streaming queue. Users build a seed session by selecting 4 to 6 tracks (identified by track id with a short acoustic profile, since the dataset contains no song titles) and tagging each as listened or skipped. The application computes the user's active session profile from the unskipped tracks, predicts skip probabilities for the upcoming queued tracks using the trained model, and displays a radar chart (energy, danceability, valence, acousticness, speechiness) showing how each candidate track differs from the user's profile.
